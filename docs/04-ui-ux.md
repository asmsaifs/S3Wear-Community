# 04 — UI / UX design system

Screen: 410×502 px, 2.06", ~326 ppi, rounded-corner rectangle (corner radius on glass ~ 60 px — `UI_SAFE_INSET` is 24 px until measured on the device). AMOLED: black = off = free power.

## 1. Principles
1. **Glanceable**: the key number on every screen readable in < 2 s, minimum 24 px body text.
2. **Black canvas**: background `#000000` always. Colour used for meaning, not decoration.
3. **Fat fingers**: touch targets ≥ 64×64 px (≈ 8 mm), spacing ≥ 8 px.
4. **One task per screen**, vertical scrolling lists, no nested scroll in the same axis.
5. **Fast**: transitions ≤ 200 ms, 30+ fps; nothing blocks input.
6. **Consistent physical controls**: PWR = home/wake, BOOT = back.

## 3. Navigation model

```
                    Quick Settings (swipe down)
                              ▲
 Launcher  ◀── swipe right ── WATCH FACE ── swipe left ──▶ Tiles (widget carousel)
 (BOOT key)                   │
                              ▼
                    Notifications (swipe up)
```
- Inside apps: swipe from left edge = back (and BOOT key). Screens form a stack (`nav_push`, `nav_pop`, `nav_home`).
- Implemented in P3-06 (§4b): the face forwards its swipes to `ui_nav_home_swipe()`, which pushes the panel with a slide from the opposite side; the panel closes with the reverse swipe, BACK or PWR. BOOT on the face opens the launcher.
- Tiles: horizontal pages, each a compact widget (Activity rings, Weather, Media, Next event, Timer, Heart rate if available, HA tile, mini app tiles). User orders tiles on watch or phone (not yet: fixed order, §4b).
- Launcher: vertical list with icons (default) or honeycomb grid (setting). Sections: Recent, System apps, Mini apps, Games.
- Overlays: toast (top), banner notification (top, 4 s), full-screen alerts (alarm, call, timer done, low battery) which preempt everything.

## 4. Screen lifecycle (ui_framework)
API in `ui_framework/include/ui_nav.h`, implemented in `ui/nav.c`. Everything runs on the UI task (other tasks use `s3w_ui_post()` or `lv_lock()`).
```c
typedef struct {
  const char *id;                                   // unique; ui_nav_push_id(), logs, console
  void (*on_create)(ui_screen_t *s, lv_obj_t *root, const void *args);
  void (*on_resume)(ui_screen_t *s);   // visible again, re-subscribe to events
  void (*on_pause)(ui_screen_t *s);    // covered or screen off: stop timers/animations
  void (*on_destroy)(ui_screen_t *s);
  bool (*on_back)(ui_screen_t *s);     // return true if handled
  uint32_t flags;                      // UI_SCREEN_KEEP_ON, UI_SCREEN_FULLSCREEN, UI_SCREEN_NO_SWIPE_BACK
  size_t state_size;                   // zeroed per-instance state, ui_screen_state(s)
} screen_def_t;
```
- Order: `on_create` → `on_resume` → (`on_pause` ↔ `on_resume`)* → `on_pause` → `on_destroy`. Only the top screen is "visible", and only while the display is on (`ui_nav_set_active()`, called from `svc_power`'s UI hook in `app_main`) and no full-screen alert covers it.
- Screens must stop their animations in `on_pause`. Timers made with `ui_screen_timer_create()` (up to 4 per screen) are paused, resumed and deleted by the framework.
- `ui_nav_push/pop/back/home`, stack depth ≤ 8 (`UI_NAV_MAX_DEPTH`), the home screen at the bottom. `ui_nav_back()` first offers BACK to a full-screen alert, then to the top screen's `on_back`, then pops. `ui_nav_register()` + `ui_nav_push_id()` open screens by id (console `ui push <id>`, simulator scripts, later deep links).
- All screens are full-size containers on one LVGL screen. The framework does the 200 ms slide itself, not `lv_screen_load_anim()`: that call ignores a pop that comes before a running push has started (fast double input) and leaves a stale screen. `ui_nav_push()` slides in from the right; `ui_nav_push_slide(def, args, UI_SLIDE_FROM_LEFT/TOP/BOTTOM)` from another side, and the pop slides the screen back out the way it came.
- A pop while a finger is still down (a swipe closed the screen) drops that press and ignores the touch until it ends, so no release reaches a widget whose screen state `on_destroy` already freed (the old root lives on for the 200 ms slide).
- Home panels: `ui_nav_set_home_swipe(dir, def)` registers the screen a swipe in finger direction `dir` on the home screen opens; the home screen's gesture handler calls `ui_nav_home_swipe(dir)` (only at depth 1 and with no alert).
- Edge swipe: a 24 px strip on the top layer along the left edge. A drag of ≥ 80 px to the right (more horizontal than vertical) calls `ui_nav_back()`, with a knob that follows the finger. It is off on the home screen, under alerts and with `UI_SCREEN_NO_SWIPE_BACK`.
- Buttons: `app_main` maps `svc_input` actions (P2-07): BOOT → `ui_nav_back()`, or the launcher on the home screen (P3-06); PWR → `ui_nav_home()`, or screen off on the home screen; PWR held 2 s → power menu; BOOT held 1 s (shortcut) and PWR triple-press (SOS) show a toast until those features exist. A press that wakes the screen does nothing else. A palm over the screen turns it off. The simulator maps BOOT → back (launcher on the home screen) and PWR → home directly.
- Power menu (`ui_power_menu_screen`, id `power`, P2-06): Power off and Restart (each confirmed with `s3w_dialog_show`), Battery saver toggle, Watch only (confirmed), battery %. Actions go to the `on_action` handler in its push args, so the screen has no service dependency.
- `UI_SCREEN_KEEP_ON`: `app_main` follows the top screen through `ui_nav_set_listener()` and holds the screen on while such a screen is visible.
- Clock: `ui_clock_bind_label()` keeps a label at "HH:MM" (or 12 h via `ui_clock_set_24h()`, from `svc_time` at boot and on every `TIME_24H` change), with one timer wake-up per minute, aligned to the minute and paused while the display is off. `ui_clock_set_source()` lets the simulator pin the time. While the time is unknown (`ui_clock_set_valid(false)`, from `svc_time`) every clock shows `--:--`; `ui_clock_bind_unknown(obj, show_when_unknown)` shows or hides an object with that state (home: "Time not set" hint). `ui_clock_refresh()` re-renders and re-aligns after a time, zone or DST change.
- Diagnostics that load their own screen with auto-delete (`lcd bars`, `lcd demo`, `factory test`) take the navigation down with it: every screen gets `on_pause`/`on_destroy` and the stack is empty. Console `ui home` starts it again.
- Console: `ui nav` (print the stack), `ui push <id>`, `ui back`, `ui home`, `ui toast <text>`.
- Home: the watch face (`wf_home_screen`, id `face`, §4a). `wf_init()` installs it with `ui_set_home()`; `ui_start()` registers the gallery and power menu and fades from the boot screen to home. The widget gallery opens from the launcher (**Widgets**) or with console `ui push gallery`.
- Clock listeners: `ui_clock_add_listener()` runs a callback after every clock re-render (minute tick, display on, 12/24 h or "time valid" change, `ui_clock_refresh()`); the watch face engine uses it instead of its own minute timer.

### 4a. Watch faces (`components/watchfaces`, P3-02)
Portable (LVGL + `ui_framework`), built by the watch and the simulator (`watchfaces/sources.cmake`).
- **Engine** (`wf_engine.h`): a face is a `wf_face_def_t` (id, name, flags, complication slots, `create(f, root)` building the normal or AOD variant, `update(f, changed)`). The home screen hosts the active face and rebuilds it on `wf_set_active(id)` or `wf_set_aod(on)`. Updates come from the minute clock (`ui_clock_add_listener`), `wf_data_changed(mask)` and, only for `WF_FACE_SECONDS` faces while the screen is on and not in AOD, a 1 s timer (second hand). Changes while the face is hidden are applied when it is shown again. Up to 16 faces (`wf_register`).
- **Complications** (`wf_comp.h`, pure C): battery, steps, date, weather, next event, sunrise/sunset, world time, phone battery, heart rate, alarm, timer (minute resolution), notifications, moon phase. Each has a stable id, the data it depends on and the app id a tap opens. `wf_comp_render()` makes a view (value, ≤ 5-letter caption, detail, gauge 0..1000, colour); unknown data shows `--` in dim grey. The engine draws slots as a 120 px circle (gauge ring, value, caption) or a 330 × 64 px pill (value, detail), creates them before the face content (hands draw over subdials), and on tap pushes the app's screen, or shows "<name>: no app yet" while it does not exist. Slots are not drawn in AOD. `wf_set_slot(face, n, comp)` changes a slot in memory; the customize screen saves it (below).
- **Bindings** (`wf_bind.h`, pure C): the names faces bind to (`time.hh:mm`, `date.<pattern>`, `battery.ratio`, `steps.goal_ratio`, `weather.temp`, `next_event.title`, `moon.phase`, …), with text and numeric forms, date patterns (`EEE d MMM`, `yyyy-MM-dd`, …) and dependency masks. The native faces use the same formatters; the declarative faces resolve `face.json` binds with `wf_bind_parse()`. Table in the header.
- **Declarative faces** (P3-03, format docs/03 F1 and `wf_decl.h`): `wf_json.c` is a strict JSON pull parser (no allocation, nesting ≤ 16); `wf_decl.c` (pure C) turns face.json into a fixed-size model (≤ 32 elements, ≤ 8 AOD elements, ≤ 4 complication slots) or an error with path and line:column. `wf_decl_face.c` registers the model as an ordinary `wf_face_def_t` (model ~6 KB in PSRAM): each element becomes one LVGL object (text = full-width label aligned around x, arc = `lv_arc`, hand = the shared line hand, ticks = one `lv_scale`, circle/rect = plain objects), complication elements become the face's slots, and `update()` re-reads only the bindings whose data changed. A face that binds a second-resolution value (`time.ss`, `time.second`, `time.minute`) gets the 1 s timer. Without `"aod"` the AOD variant is the time in light digits. Sample faces `s3w.neon` (cyan digits, seconds, steps ring, battery circle) and `s3w.dial` (vector analog dial, battery arc, date window, steps circle) are `watchfaces/samples/<id>/face.json`, embedded at build time (`sources.cmake` generates `wf_samples.c`) and registered by `wf_init()`; AOD lit pixels 1.9 % and 1.1 %. Installed faces: `app_main` calls `wf_decl_load_dir("/flash/faces")` after `wf_init()`; the directory name must equal the id, and every rejected file is logged with its error. Simulator: `s3w_sim --faces <dir> [--face <id>]` previews faces under development.
- **Data** (`wf_data.h`): one `wf_data_t` on the UI task (`wf_data_edit()` + `wf_data_changed(mask)`). Today `app_main` feeds the battery (`SVC_POWER_EVT_BATTERY`); steps, weather, phone, calendar, alarms and the rest join with their services. The simulator fills a fixed demo set.
- **Faces**: Digital Bold (`digital`, default: stacked 160 px hours/minutes in white/accent, date, bottom pill = battery), Analog Classic (`analog`: 60-tick dial, 12 and 6, hour/minute/second hands, subdials left = date, right = steps), Modular (`modular`: 96 px time, date, three circles steps/battery/weather, pill = next event), Minimal (`minimal`: light 96 px time, long date, empty pill slot). While the time is unknown every face shows `--` (analog: no hands) and a "Time not set" hint at the top.
- **AOD variants**: light 96 px digits (or thin hands and 12 dots) in `UI_COLOR_TEXT_DIM`, no seconds, no complications. The F1 "outline digits" are approximated by Inter Display ExtraLight: LVGL 9.3 has no outlined text. Measured lit pixels (`lit` scenario command): digital 1.9 %, analog 0.9 %, modular 1.9 %, minimal 2.4 % (limit 10 %). `svc_power`'s AOD state calls `wf_set_aod(true)` through the `app_main` UI hook. **Burn-in shift** (P3-05, `wf_shift.c`, host tests `test_wf_shift`): the AOD face root moves on every minute update along a snake over the 5 × 5 grid of even offsets −4..+4 px and back (48-minute period, 2 px per minute, offset from wall-clock minutes so a rebuild keeps it); scenario `face_digital_aod_shift`.
- **Settings** `WATCH_FACE` (`face`, default `digital`; any registered id, e.g. `s3w.neon`) and `FACE_CONFIG` (`face_cfg`, ≤ 511 characters, P3-04): applied at boot (config after every face is registered, installed ones too) and on change or settings reset. Console `face` lists faces, slots, colours and complication ids; `face <id>` switches (saved) and prints build + one-frame time; `face aod on|off` previews the AOD variant; `face slot <n> <comp|default>` sets a slot of the active face (not saved); `face config` prints the configuration in use and the saved string.
- **Picker** (`wf_picker_screen`, id `face.picker`, P3-04): a long-press (400 ms) anywhere on the face opens it, also on a complication (slots open their app on a short click only); not in AOD. One live copy of a face at a time, built by the engine (`wf_preview_create`: no slot taps, no hints, not updated) and drawn at 0.56 scale (`transform_scale`, one 410 × 502 layer while it renders) inside a glass outline, with the face name, page dots and a **Customize** button (hidden if the face has no slots and no colour). Swipe left/right = next/previous face (the release after a swipe never counts as a tap); tap the preview = wear it and go home; BACK = leave unchanged. `UI_SCREEN_NO_SWIPE_BACK` (horizontal swipes page).
- **Customize** (`wf_customize_screen`, id `face.customize`, args = face id): list of the face's slots ("Left", "Bottom", … with the current complication) and, for faces flagged `WF_FACE_COLOR`, the colour. A row opens a chooser (every complication incl. None / Default + 9 colours with swatches, the current one ticked); a choice applies at once and pops back. Colour: native faces use it for their accent element (Digital minutes, Modular/Minimal date, Analog second hand and centre dot — red by default), declarative faces for every `"accent"` colour (they get `WF_FACE_COLOR` only if they use one); "Default" = the theme accent. `wf_face_accent(f)` / `wf_face_accent_or(f, def)` give the colour to faces.
- **Saving**: the screens call the engine listener (`wf_set_listener`), `app_main` saves: `WF_CHANGE_ACTIVE` → `WATCH_FACE`, `WF_CHANGE_CONFIG` → `wf_config_save()` → `FACE_CONFIG`. The string (`wf_cfg.h`, pure C, host test `test_wf_cfg`) holds only non-default values: `<face>:<slot id>=<complication id>,color=<rrggbb>;<face>:…`, e.g. `analog:right=moon,color=40c8e0`. `wf_config_load()` skips items for faces, slots or complications that no longer exist (logged). If the string would exceed 511 characters the items that fit are saved and a toast says so.
- Swipes on the face open the shell panels (§4b); not in AOD. A swipe never ends in a complication tap.

### 4b. Shell: quick settings, notifications, tiles, launcher (`components/ui_apps`, P3-06)
Portable like the faces (`ui_apps/sources.cmake`, built by the watch and the simulator); API `shell.h`. `shell_init()` (after `wf_init()`) registers the screens and the home swipes. The screens call no service: quick settings uses a backend and the launcher a listener, both installed by `app_main` (the simulator installs an in-memory backend). All four have `UI_SCREEN_NO_SWIPE_BACK`: each closes with the swipe opposite to the one that opened it.
- **Quick settings** (id `qs`, swipe down, from the top; swipe up closes): status line (battery %, clock, phone link — dim until P4), a 4-column grid of 76 px round buttons without labels, brightness slider, a grabber at the bottom. Toggles: Do not disturb, Theater mode, Sleep mode, Always-on display, Wi-Fi, Bluetooth, Silent, Battery saver; on = accent fill, and a toast names the change ("Do not disturb on"). Actions open their app: Flashlight, Find phone, Settings ("<name>: no app yet" while it does not exist; Settings exists since P3-10). `shell_qs_backend_t`: `read()` fills the state each time the panel is shown (`available` and `on` bits, brightness, battery), `toggle(item, on)` and `brightness(pct)` (once, on release of the slider). `app_main`: DND → `DND`, Always-on → `AOD`, Silent → `SILENT` settings, Battery saver → `svc_power_set_saver()`, brightness → `DISPLAY_BRIGHTNESS` (svc_power follows these settings). DND, Theater and Sleep → `svc_modes_set()` (P3-08; they show each mode's state, schedules included; Theater turns the screen off at once). Wi-Fi and Bluetooth are dim and say "<name>: not available yet".
- **Notifications** (id `notifications`, swipe up, from the bottom; swipe down closes): placeholder empty state (notifications need the phone link, which is not part of the Community edition). It must not scroll, or the list would take the swipe down. Complication taps on the notification count open it too.
- **Tiles** (id `tiles`, swipe left, from the right): Activity (steps ring), Weather, Media (placeholder), Next event, Timer, Heart rate; a clock at the top and page dots. Values come from `wf_data` through `wf_comp_render()`, so a tile always agrees with the complication; values the display font can show use it (96 px), others the title font, and "°" is drawn beside the digits. Swipe left/right pages with a 200 ms slide, swipe right on the first tile goes back to the face, a tap opens the tile's app. Refreshed when shown and on every minute while visible; data changes while visible show at the next minute. Fixed order.
- **Launcher** (id `launcher`, swipe right or BOOT on the face, from the left; swipe left closes): header "Apps", then either a list with sections **Recent** (the last 3 apps opened through the shell, newest first; shown the next time the launcher is built), **System apps**, or a honeycomb grid (rows of 3 and 2 interlocked 100 px icons, every app in registry order). The button at the end switches layout; `shell_launcher_set_listener()` → `app_main` saves `LAUNCHER_GRID` (`launch_grid`, default list), applied at boot and on change or settings reset.
- **App registry** (`shell_app_register`, up to 48): id (= screen id, the same ids complications open), name, icon, colour, kind (system / mini / game). 18 system apps are built in (Alarms, Timer, Stopwatch, World clock, Activity, Heart rate, Weather, Media, Calendar, Notifications, Find phone, Flashlight, QR wallet, Level, Battery, Watch faces, Settings, Widgets). `shell_app_open()` pushes the app's screen and records it as recent, or toasts "<name>: no app yet".
- Icons are `LV_SYMBOL_*` glyphs (the fonts have no others yet); several are stand-ins (Do not disturb = minus, Flashlight = bolt, Heart rate = plus).

### 4c. Clock apps: alarms, timer, stopwatch, world clock (`components/ui_apps`, P3-07)
API `clock_apps.h`; registered by `shell_init()`. Like the shell, the screens call no service: a `clock_backend_t` (alarms get/put/delete, next alarm, timers get/start/action, ring snooze/dismiss) installed by `app_main` over `svc_alarm`, in memory in the simulator (`sim_clock.c`, same `alarm_sched`/`timer_set`). The backend reports back with `clock_apps_changed()` (deferred to the next LVGL run, then the visible list is rebuilt and `wf_data` gets the next alarm and the earliest timer end), `clock_apps_ring()` and `clock_apps_ring_end()`. Orange (`0xFF9F0A`) is the accent of these apps.
- **Alarms** (id `alarms`): "Next in 20 h 51 min" (or "Time not set"), one row per alarm (time in 24 h or "7:00 AM", repeat days and label or "Snoozed", an on/off switch that saves at once), Add alarm (toast at 16). Rebuilt on every show. **Editor** (`alarms.edit`, pushed with an `alarm_t`): 24 h hour and minute pickers in either clock format, seven day chips Monday first with the repeat text under them ("Once", "Mon-Fri", ...), Snooze row (tap cycles 5/10/15 min), Save (turns the alarm on), Delete (confirmed). A new alarm starts at the next full hour.
- **Ring screen** (pushed by `clock_apps_ring()` above any depth, after clearing overlays; `UI_SCREEN_FULLSCREEN | NO_SWIPE_BACK | KEEP_ON`; BACK does nothing): alarm — bell, label or "Alarm", the time in the 96 px display font, "Snooze N min", and a 320 × 72 slider whose knob must be dragged to the end (`LV_OBJ_FLAG_ADV_HITTEST`: a tap on the track does nothing) to stop it; timer — the duration, "Time's up", Stop and Restart. PWR snoozes an alarm and stops a timer (`clock_apps_ring_key()` from `app_main`'s HOME action). The screen closes itself on a button, then the backend reports the end; when snoozed a toast says "Snoozed for N min". The same ring again is ignored, so `app_main` can also check `svc_alarm_ringing()` after boot.
- **Timer** (id `timer`): running, paused and done timers (time left in the title font, "Of 05:00" / "Paused, ..." / "Done, ...", pause/resume or restart, remove), then presets 1, 3, 5, 10, 15, 30 min (96 px round buttons) and Custom (`timer.custom`: h/min/s pickers, Start). Labels refresh at 4 Hz while visible.
- **Stopwatch** (id `stopwatch`): "MM:SS" in the tabular display font with ".cc" beside it ("H:MM:SS" from an hour on), Lap/Reset and Start/Stop round buttons, laps newest first. The state is outside the screen on the LVGL tick: it keeps running with the app closed. 20 fps while running and visible, nothing while stopped.
- **World clock** (id `world_clock`): one row per city (name; "Today, +9 h", "Tomorrow, +5:30 h"; local time), tap → "Remove <city>?", Add city (`world_clock.add`: every built-in city not shown yet, with its time). Refreshed on the minute while visible. The list is the `WORLD_CLOCKS` setting (`clock_apps_set_world()` / listener; `app_main` saves it).

### 4d. Battery screens and low-battery flows (`components/ui_apps`, P3-09)
API `battery_apps.h`; registered by `shell_init()`. The screens call no service: a `battery_backend_t` (read, set saver, enter watch-only) installed by `app_main` over `svc_power` (`svc_power_battery_info()`), in the simulator over the fake battery (`sim_battery.c`, demo history on the same `battery_hist.c`). `app_main` reports `battery_apps_changed()` (every reading and saver change; the open screen re-reads), `battery_apps_charger(vbus)` (USB power came or went), `battery_apps_screen_on()` (screen woke) and `battery_apps_low()`.
- **Battery app** (id `battery`, launcher): 260 px ring in the level colour (green, yellow ≤ 20 %, red ≤ 10 %) with the percentage, the state ("On battery", "Battery saver on", "Charging", "Charged", "Not charging") and the estimate ("About 8 h left", "Full in about 1 h 20 min", "Estimating time left" until the gauge moved 2 % over 10 min). "Last 24 hours": 24 hourly bars (the last reading of each hour; charging hours in the accent colour, none without a reading). Battery saver switch, Watch only (confirmed), Voltage.
- **Charging screen** (id `charging`, slides up from the bottom): when USB power arrives, and on every screen wake on USB power while the face is on top; not over a ringing alarm or an alert. 300 px green ring with ⚡ and the percentage, a bright 30° segment running round it while charging (10 fps, only while visible), "Charging" / "Charged" and the time to full. A tap or BACK goes back to the face; unplugging closes it.
- **Low battery** (`svc_power` posts each threshold once until USB power returns; it wakes the screen for 10 % and 3 % except in DND, sleep and theater mode): 15 % a "Battery 15%" toast (`svc_audio` plays the low-battery sound at every threshold unless Silent or a quiet mode); 10 % an alert "Turn on battery saver?" (Turn on / Not now; with saver already on, a toast); 3 % an alert "Watch only starts in a minute" (Start now / OK) — `svc_power` enters WATCH-ONLY at the second ≤ 3 % reading 60 s later.
- **Watch-only screen** (`ui_watch_only_show()`, `ui_root.h`, ui_framework): the time in the 96 px light digits and the battery % (red ≤ 10 %) on black, moved by the AOD burn-in step of its minute (`wf_aod_shift`); ~1.7 % of the pixels lit. Drawn when WATCH-ONLY starts and by each minute tick boot (docs/02 §7).

### 4e. Settings app (`components/ui_apps`, P3-10)
The tree of docs/03 F18 as data (`settings_tree.c`, host-tested against the settings schema), drawn with the standard list widgets. Id `settings` (launcher, quick settings button) is the top page; `settings.page` is every sub page, `settings.choice` a list of options with a tick on the current one, `settings.time` hour and minute pickers with Save (24 h pickers in either clock format, as the alarm editor). A page re-reads its values when it comes back on top and keeps its scroll position.
- **Rows**: sub page (chevron), switch (tap anywhere), slider (saved when released), choice (current value on the right, "Custom" if the stored value is not an option), time, time zone (UTC and the world clock cities), action (confirm dialog; Factory reset and Forget phone in red), info (read only), app link (Watch faces, Battery details), "Soon" (toast "<name>: not available yet").
- **Pages**: Display (brightness, timeout, AOD, raise to wake + sensitivity, wake on tap), Sound (silent, three volumes, haptics), Notifications (wake on alert, Do not disturb and Sleep mode schedules: days Off / Every day / Weekdays / Weekends, from, to), Watch faces, Connections (Bluetooth and Wi-Fi soon, Forget phone), Battery (saver, details), Accessibility (large text, high contrast: stored, no effect yet), Language & region (24 h, time zone, language), System (About, Developer options, Restart, Power off, Factory reset). Apps, Health and Security say "Soon".
- **Backend** (`settings_app_backend_t`): `get_int`/`set_int` (bool as 0/1), `get_str`/`set_str`, `action`, `about`. `app_main` maps them to `svc_settings`; Battery saver goes through `svc_power_set_saver()`; Restart / Power off to `svc_power`; Factory reset to `svc_settings_factory_reset()` and a restart; Forget phone returns `ESP_ERR_NOT_SUPPORTED` until P4.
- **Simulator**: `sim_settings.c` keeps the values in memory with the same `settings_store.c`; scripts set and check them with `setting <nvs-key> <value>` and `setting-is`.

### Overlays (`ui_overlay.h`, on `lv_layer_top()`)
- Toast: one pill at the top. A new toast replaces it. Fades in over 120 ms and out after 2 s (default).
- Banner: icon, title and one-line body at the top for 4 s. Tap → `on_tap`. A new banner replaces it. Not shown under an alert or over a `UI_SCREEN_FULLSCREEN` screen.
- Full-screen alert: icon, title, body, up to two buttons and a result callback (button 0/1, or -1 for BACK). It pauses the top screen. A higher priority replaces the current alert, which then waits in the single waiting slot. An equal or lower priority waits until the current one closes. `back_dismisses = false` for alarms and calls, so BACK is swallowed. Strings are copied.

## 5. Standard components (`ui_framework/include/ui_widgets.h`)
Builders that return plain LVGL objects with the tokens applied: `s3w_list_create` (inset vertical scroll list; put `s3w_header_create` first so the title scrolls away), `s3w_list_add_section`, `s3w_list_add_row` (icon, title, subtitle, trailing value), `s3w_toggle_row` (the whole row toggles the switch), `s3w_slider_row` (value + unit; touch area ≥ 64 px), `s3w_button_create` (pill primary/secondary/danger, ≥ 64 px high), `s3w_card_create`, `s3w_ring_create` (activity ring), `s3w_picker_create` (rolling numeric, zero-padded), `s3w_page_dots_create`, `s3w_header_create` (clock + title, centred), `s3w_dialog_show` (confirm, covers the screen), `s3w_empty_state_create`, `s3w_qr_create` (white quiet zone), `s3w_label_fit` / `s3w_label_set_fit_text` (cut a label's text with "..." to fit its box: the content size, or max width / max height while sized to content). Toast = `ui_toast_show()`.
- **Never use `LV_LABEL_LONG_MODE_DOTS`.** It rewrites the label's own text buffer in place (puts the characters under the dots back to measure, then writes the dots again) while the draw task on the render thread ("swdraw") reads that buffer. A label drawn in more than one band could be measured on the full text and walked on the cut one: `lv_draw_label` loops forever on the `'\0'` and the task watchdog fires on CPU 1 (found with a long Bangla title; the simulator draws on one thread in one pass and does not show it). `s3w_label_fit` keeps the label in WRAP mode and only ever sets a finished string on the UI task. Still to come: `s3w_keyboard_t9` (P2: small text entry).

Rows and lists use shared `lv_style_t` objects, not local styles. No style or state changes happen while a list scrolls (docs/02 §6).

Widget gallery: home → **Widgets**, or `ui push gallery` on the console. Pages: `gallery.buttons`, `.lists`, `.rings`, `.picker`, `.overlays`, `.qr`, `.empty`, `.text`.

## 7. Design workflow
1. Mock each screen in the simulator directly (fast) or Stitch/Figma for key screens.
2. Every screen gets a scripted simulator scenario (`firmware/test/ui/<name>.txt`, format in its README) whose PNG must match `firmware/test/ui_snapshots/<name>.png` (`ctest --test-dir build/sim`, run in CI).
3. Accessibility checks: contrast ≥ 4.5:1 for body text, targets ≥ 64 px, large-text mode screenshots.
